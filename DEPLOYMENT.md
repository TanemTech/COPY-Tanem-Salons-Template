# TANEM — обязательный маршрут публикации

Этот файл определяет единый порядок работы ChatGPT технического специалиста для каждого нового клиентского сайта.

## Что должно быть до начала

Обязательно:
- ссылка на клиентский GitHub-репозиторий;
- ссылка на карточку бизнеса/мастера;
- в репозитории уже лежат `business.json` и фотографии.

Если ссылка на репозиторий не дана — сначала запросить её. Не вносить изменения в неизвестный репозиторий.
Не просить повторно данные, которые уже есть в `business.json`, фотографиях или переданной карточке.

Желаемый поддомен можно дать сразу или перед production-публикацией. Формат: `slug.tanem.ru`, например `monroe.tanem.ru`. ChatGPT не должен сам окончательно назначать клиенту другой адрес без прямого указания пользователя.

## Обязательный порядок

1. Проверить репозиторий и определить, подходит ли выбранный шаблон: Salon или Master.
2. Прочитать `business.json`, фотографии и переданную карточку.
3. Собрать сайт строго по правилам текущего шаблона.
4. Запустить все обязательные проверки.
5. Только после зелёных проверок внести изменения в `main`.
6. Запустить автопубликацию GitHub Pages для проверенного коммита по инструкции ниже.
7. Вернуть реальную Pages-ссылку только после успешной публикации.
8. Только после явного подтверждения пользователем проверенной версии зафиксировать commit SHA. Если задан production-поддомен, проверить его формат и передать его только в утверждённый автоматический production-deploy.
9. Проверить, что production-сайт реально открывается по HTTPS.
10. Только после этого сообщить, что сайт полностью опубликован.

## Автопубликация превью GitHub Pages

Команда для нового сайта в Codex:

> Собери сайт TANEM из этого репозитория и пришли рабочую ссылку на превью через GitHub Pages Actions. <ссылка на репозиторий>

Обычный ChatGPT со стандартным подключением GitHub может читать репозиторий. Для сборки с автоматическим включением Pages запускайте команду в Codex с настроенным GitHub-доступом.

После проверок и отправки проверенного коммита в `main` запустите из актуальной копии шаблона:

```bash
bash scripts/publish-pages.sh TanemTech/ИМЯ_РЕПОЗИТОРИЯ SHA_ПРОВЕРЕННОГО_КОММИТА
```

Команда работает с указанным клиентским репозиторием. Она включает Pages с источником GitHub Actions, запускает существующий `.github/workflows/pages.yml`, проверяет этап `deploy` для указанного коммита и открывает полученный URL превью по HTTPS. В результате возвращает URL сайта, URL запуска Actions и SHA коммита. Если Pages уже настроен на Actions, команда использует имеющиеся настройки. Собственный домен требует отдельного маршрута публикации.

### Подключение доступа в Codex Cloud

1. В GitHub создайте fine-grained personal access token для владельца `TanemTech`. Разрешения репозитория: `Administration: Read and write`, `Pages: Read and write`, `Actions: Read and write`, `Contents: Read-only`. Выберите клиентские репозитории. Чтобы автоматически включать будущие репозитории без их ручного добавления, GitHub предлагает `All repositories`. Этот выбор даёт токену перечисленные права на все репозитории владельца.
2. В настройках облачной среды Codex сохраните токен как **HTTP secret** с ключом `TANEM_PAGES_TOKEN` и единственным разрешённым доменом `api.github.com`. Добавьте `tanemtech.github.io` в разрешённые домены среды для проверки превью. Сохраните и опубликуйте среду, затем откройте новую задачу в ней.
3. Проверьте первый запуск на новом клиентском репозитории. После этого используйте ту же среду и команду для следующих сайтов. При истечении срока действия обновите сохранённый секрет.

## Граница доступа

ChatGPT технического специалиста:
- работает с GitHub;
- не входит вручную в REG.RU;
- не входит в Selectel;
- не получает пароль REG.RU, API-ключ REG.RU, пароль Selectel или root-доступ к VPS;
- не редактирует DNS, Nginx или SSL вручную;
- не придумывает собственный способ публикации.

DNS, Selectel, Nginx и SSL должны выполняться отдельной утверждённой автоматикой.

Пока production-автоматика не подключена, разрешено:
- собрать сайт;
- опубликовать и проверить GitHub Pages;
- сообщить, что production-домен ещё не подключён.

Запрещено заявлять, что `*.tanem.ru` работает, если это не было фактически проверено.

## Если что-то сломалось

Не пытаться чинить инфраструктуру случайными ручными действиями.

Нужно:
1. назвать конкретный упавший этап;
2. показать конкретную ошибку;
3. не трогать уже работающую production-версию;
4. после исправления повторить стандартный pipeline.

## Финальный ответ техническому специалисту

Коротко:
- Сборка: OK / ошибка.
- Проверки: OK / ошибка.
- GitHub Pages: <реальная ссылка> / не опубликовано.
- Production: <реальная ссылка> / ещё не подключён.
- Найденные проблемы: только конкретные факты.
