# TANEM — обязательная инструкция агенту

Этот репозиторий является производственным шаблоном сайтов салонов TANEM. В обычном режиме Chat файл не загружается автоматически, поэтому проектная инструкция направляет ChatGPT в `START_HERE.md`. Codex читает этот файл автоматически и также обязан следовать `START_HERE.md`.

## Перед первой правкой

1. Прочитайте `START_HERE.md` целиком.
2. Прочитайте `DEPLOYMENT.md` целиком.
3. Прочитайте `RULES.md` и `docs/FACTORY_GUIDE.md` целиком.
4. Для создания клиентского сайта используйте данные из текущего чата, приложенных файлов и переданных пользователем ссылок. Пользователь не обязан перекладывать их в специальную форму: агент сам исследует источники, извлекает и структурирует факты по `docs/INPUT_CHECKLIST.md`.

## Обязательный вход

Для нового клиента технический специалист передаёт:
- ссылку на клиентский GitHub-репозиторий;
- ссылку на карточку салона;
- желаемый поддомен, если он уже выбран.

В самом репозитории должны находиться `business.json` и фотографии. Если ссылка на репозиторий не передана — запросить её до любых изменений.

Публикацию и финальный статус выполнять строго по `DEPLOYMENT.md`.

## Простой вход из корня клиентского репозитория

Оператор может загрузить прямо в корень клиентского репозитория:
- `business.json`;
- исходные фотографии с любыми понятными именами;
- логотип, если он есть.

В этом режиме пользователь не обязан заранее создавать папки, переименовывать фотографии или распределять их по ролям.

1. Сначала прочитайте корневой `business.json` целиком.
2. Просмотрите все переданные клиентские изображения и определите их назначение по содержимому и правилам `RULES.md`.
3. Подготовьте канонические файлы `hero.webp`, `profile.webp`, `gallery-XX.webp`, `team-XX.webp` и `logo.*` только там, где для роли действительно есть подходящий исходник.
4. Не угадывайте клиентские факты по фотографии, если они не подтверждены данными.
5. Если одновременно присутствуют корневой `business.json` и старый экспорт в `intake/yandex/`, не смешивайте противоречащие значения молча: используйте прямое указание пользователя как приоритет, а неразрешимый конфликт кратко обозначьте.

## Вход из TANEM Exporter

Если в клиентском репозитории существует `intake/yandex/business.json`, это поддерживаемый машинный источник для нового сайта.

1. Сначала прочитайте `intake/yandex/business.json` целиком и извлеките из него все доступные факты.
2. `intake/yandex/business.txt` используйте только как человекочитаемое дополнение, если JSON не даёт нужного контекста.
3. `intake/yandex/ПРОВЕРКА.html` используется только для ручной сверки и не является источником правды поверх JSON.
4. Просмотрите `intake/yandex/assets/` и распределите реальные изображения по каноническим ролям `hero.webp`, `profile.webp`, `gallery-XX.webp`, а при наличии подтверждённой команды — `team-XX.webp`.
5. Не заставляйте пользователя повторно присылать данные, уже находящиеся в `intake`. Во внешние источники переходите только для обязательного поля, которого нет в экспорте, либо для разрешения конфликта.
6. Не переносите в клиентский репозиторий диагностические файлы экспортёра (`export.log`, `debug/`) и любые cookies, токены, ключи или сессионные данные.
7. `intake/` — производственный вход для агента, а не содержимое сайта. Workflow публикации GitHub Pages не должен включать эту папку в публичный артефакт.

## Работа с несколькими репозиториями

В одном чате можно вести несколько клиентских репозиториев. Каждый репозиторий обрабатывается как отдельный клиентский контекст: данные, фотографии и клиентские сущности одного репозитория не переносятся в другой без прямого указания пользователя.

## Основной режим — новый клиентский сайт

- Сначала выполните этап исследования и один раз запросите все недостающие обязательные данные по `START_HERE.md`. Только после этого начинайте сборку.
- Начните сборку с копии `site-data.blank.js` в `site-data.js`.
- Список услуг, цены, длительности и варианты берите из явного списка пользователя. Не восстанавливайте каталог услуг по догадке из Яндекс Карт.
- Не выдумывайте название, адрес, график, описание, опыт, рейтинг, отзывы, контакты, услуги, цены, сотрудников или ссылки.
- Сразу разделяйте адрес: `salon.city` и `salon.address` — короткие строки интерфейса, `salon.fullAddress` — полный проверенный адрес. Для RU обязательны Яндекс `mapUrl`/`mapEmbedUrl`, для остальных стран — Google Maps. Пустой мессенджер не создаёт карточку контакта.
- Не добавляйте выдуманные данные ради заполнения раздела. `team` и `reviews` можно оставить пустыми: пустой `team` визуально даст четыре системные нейтральные карточки «Мастер», а отзывы — нейтральное состояние. Эти карточки не являются реальными сотрудниками.
- Если отсутствует обязательный факт, который невозможно безопасно оставить пустым, задайте один короткий объединённый вопрос. Не переспрашивайте уже переданные данные.
- В клиентском выпуске меняйте только `site-data.js`, реальные медиа, favicon/метаданные и явно разрешённые клиентские сущности. Не меняйте утверждённый дизайн, компоненты, CSS, desktop/mobile-механику и структуру карточек услуг.
- Считайте данные пользователя в текущем чате приоритетными. При конфликте с внешним источником не выбирайте молча: сообщите о конфликте и запросите решение.
- Перед завершением установите `mode: 'production'`, удалите все демонстрационные данные и выполните обязательные проверки из `docs/FACTORY_GUIDE.md`.
- Работа завершена только после проверки desktop, mobile, ссылок, языков, отсутствующих блоков и зелёных автоматических тестов.
- После зелёных проверок публикацию выполнять по `DEPLOYMENT.md`.

## Режим изменения самого шаблона

Если пользователь прямо просит изменить общий шаблон, сначала проверьте, не является ли проблема только ошибкой клиентских данных. Изменение повторяемой механики делайте в шаблоне, сохраняйте утверждённый дизайн и запускайте полный regression-набор. Не переносите данные реального клиента в `main` шаблона.

## Запреты

- Не начинайте работу с общего обзора и повторного проектирования сайта: каркас уже утверждён.
- Не создавайте новые альтернативные имена медиа.
- Не копируйте карточки услуг вручную в `desktop.js` или `mobile.js`.
- Не публикуйте `mode: 'template'`, демонстрационные записи, `#` вместо ссылок или placeholder-медиа.
- Не меняйте `RULES.md`, `AGENTS.md` или производственный контракт ради одного клиента.
