# START HERE — создание сайта салона в обычном Chat

Это главная точка входа для нового ChatGPT без памяти о TANEM. При каждом новом клиенте сначала заново откройте актуальные файлы этого репозитория: `START_HERE.md` → `DEPLOYMENT.md` → `RULES.md` → `docs/INPUT_CHECKLIST.md` → `docs/FACTORY_GUIDE.md`.

Не анализируйте заново архитектуру и не переделывайте дизайн. Шаблон уже утверждён. Задача — собрать достоверные данные, запросить недостающее одним сообщением и заполнить клиентский сайт.

## Что должен передать технический специалист

Обязательно:
- ссылку на клиентский GitHub-репозиторий;
- ссылку на карточку салона.

В репозитории:
- `business.json`;
- исходные фотографии;
- логотип, если он есть.

Желаемый поддомен можно передать сразу или перед production-публикацией.

Если ссылка на репозиторий отсутствует — запросить её до начала работы. Не просить повторно данные, которые уже лежат в репозитории.

## Самый простой вход

Технический специалист может просто загрузить в корень клиентского репозитория:
- `business.json`;
- все исходные фотографии;
- логотип, если он есть.

Предварительно раскладывать фотографии по папкам или переименовывать их не требуется. Агент сам просматривает материалы, извлекает факты из `business.json` и готовит медиа по каноническим ролям из `RULES.md`.

Если по содержимому данных видно, что клиент является частным мастером, а не салоном, не собирайте его на салонном шаблоне: используйте актуальный `Shablon-For-Only-Masters`.

Если в одном чате передано несколько репозиториев, работайте с каждым независимо и не смешивайте клиентские данные или фотографии.

## Если данные уже выгружены TANEM Exporter

Поддерживаются оба варианта:
- простой вход из корня: `business.json` + исходные изображения;
- прежний вход: `intake/yandex/business.json` + `intake/yandex/assets/`.

Если используется прежний экспорт, не просите пользователя заново присылать карточку или вручную раскладывать сведения.

- `business.json` — основной источник данных экспортёра.
- `business.txt` — вторичный человекочитаемый слой.
- `assets/` — загруженные исходные фотографии.
- `ПРОВЕРКА.html` — только ручная сверка результата экспортёра.
- `export.log`, `debug/` и другие диагностические файлы в клиентский репозиторий не переносятся.

Сначала извлеките максимум фактов из JSON и медиа. Только после этого открывайте внешние ссылки для обязательных полей, которых не хватает, или для разрешения противоречий. Пользователь не должен повторно копировать информацию из экспортёра в чат.

## Этап 1. Исследование

Пользователь присылает одну или несколько ссылок: Яндекс Карты, Google Maps, 2ГИС, сайт салона, DIKIDI, YCLIENTS, социальные сети или другие источники. Также он может прислать CRM-карточку, фотографии, логотип, контакты и список услуг.

1. Откройте все переданные источники, которые доступны.
2. Соберите максимум подтверждённых данных по `docs/INPUT_CHECKLIST.md`.
3. Сопоставьте источники и данные пользователя. Последнее прямое сообщение пользователя имеет приоритет. Конфликтующие значения не выбирайте молча.
4. Явный список услуг пользователя является окончательным. Если услуги видны только во внешнем источнике, их можно собрать как предварительные, но перед выпуском нельзя дополнять каталог догадками.
5. Не начинайте заполнять клиентский репозиторий, пока не определено, каких обязательных данных не хватает.

## Этап 2. Один отчёт о данных

После исследования ответьте один раз:

```text
Я собрал доступную информацию.

Найдено:
- ...

Для сборки сайта не хватает:
- ...
```

- Не спрашивайте то, что уже найдено.
- Все обязательные пробелы и противоречия объедините в одно сообщение.
- Отсутствие реальных команды или отзывов не является блокером: пустая команда визуально получит четыре системные нейтральные карточки «Мастер», отзывы — нейтральное состояние; реальные данные не выдумываются.
- Если обязательных пробелов нет, прямо сообщите, что данных достаточно, и переходите к сборке.

## Этап 3. Сборка

После ответа пользователя:

1. Скопируйте `site-data.blank.js` поверх `site-data.js` в клиентском репозитории.
2. Заполните только подтверждённые данные. Для адреса отдельно заполните короткие `salon.city` / `salon.address` и полный `salon.fullAddress`; подключите `mapUrl` и `mapEmbedUrl` правильного провайдера для страны.
3. Сохраните утверждённые универсальные `salon.heroDescription` и `salon.about` из `site-data.blank.js` без изменений.
4. Структурируйте услуги, подключите ссылки и распределите медиа по `RULES.md`.
5. Если нет команды или отзывов, оставьте соответствующие массивы пустыми. Шаблон сам покажет четыре системные карточки мастеров и нейтральное состояние отзывов.
6. Не меняйте HTML, CSS, desktop/mobile-механику или дизайн ради клиента.
7. Проверьте desktop, mobile, языки, ссылки и выполните все команды из `docs/FACTORY_GUIDE.md`.

## Утверждённые универсальные тексты

### Первый экран — `salon.heroDescription`

На главном экране ПК всегда используется:

> Ваша красота. Ваша уверенность.

> Your beauty. Your confidence.

### Блок «О салоне» — `salon.about`

На ПК и мобильной версии всегда используется один и тот же текст:

> В основе нашей работы — профессиональный подход, внимание к деталям и уважение к индивидуальности каждого гостя. Мы создаём комфортное пространство, где качество и забота остаются главным приоритетом.

> Our work is built on professionalism, attention to detail, and respect for every guest’s individuality. We create a comfortable space where quality and care remain our highest priorities.

Эти тексты являются частью утверждённого шаблона, а не данными конкретного клиента. Не переписывайте и не персонализируйте их без прямого поручения владельца шаблона. Для дополнительного языка переводится тот же утверждённый смысл.

## Этап 4. Публикация и финальный статус

Публикация выполняется строго по `DEPLOYMENT.md`.

Нельзя говорить «сайт готов», если остались незаполненные обязательные поля, заглушки, неработающие ссылки, не пройдены проверки или заявленная ссылка фактически не открывается.

Финальный ответ должен содержать:
- Сборка: OK / ошибка.
- Проверки: OK / ошибка.
- GitHub Pages: реальная ссылка / не опубликовано.
- Production: реальная ссылка / ещё не подключён.
- Найденные проблемы: только конкретные факты.
