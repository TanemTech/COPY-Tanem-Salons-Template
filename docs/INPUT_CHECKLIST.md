# Входные данные клиента

Это не анкета, которую пользователь обязан заполнять вручную. Агент сначала исследует все переданные ссылки, затем сам собирает этот набор из источников, текущего чата, CRM-карточки и приложенных файлов.

## Источники и приоритет

Проверяйте все переданные источники: Яндекс Карты, Google Maps, 2ГИС, официальный сайт, DIKIDI/YCLIENTS, социальные сети и другие страницы клиента.

Приоритет при конфликте:

1. последнее прямое сообщение пользователя;
2. переданная CRM-карточка и клиентские файлы;
3. официальный сайт или сервис онлайн-записи;
4. карточки Яндекс/Google/2ГИС;
5. социальные сети и остальные источники.

Не используйте приоритет молча, если расходятся важные сведения: адрес, телефон, график, цены или ссылка записи. Покажите конфликт в едином запросе недостающих данных.

## Как разбирать вход

Для каждого пункта внутренне определите состояние: `получено`, `явно отсутствует`, `неизвестно` или `есть конфликт`.

- `получено` — перенести без смыслового искажения;
- `явно отсутствует` — не выдумывать сущность; отображение блока определяется `RULES.md` (например, команда сохраняет четыре системные нейтральные карточки, а карточка отсутствующего мессенджера не создаётся);
- `неизвестно` — не придумывать; спросить только если поле обязательно для выпуска;
- `есть конфликт` — показать пользователю два значения и запросить выбор.

Не просите пользователя повторно оформлять уже присланные сведения по этому списку.

## Что извлекается

### Салон

- название и вид салона;
- страна; полный проверенный адрес; отдельно короткий город и короткий адрес для интерфейса (`salon.city`, `salon.address`, `salon.fullAddress`);
- подтверждённый рейтинг и количество оценок.

### Работа и запись

- часовой пояс и график по дням;
- телефон;
- Telegram, WhatsApp, MAX или другой переданный мессенджер: название платформы, ссылка и handle, если он есть;
- `mapUrl` и `mapEmbedUrl`: для России обе ссылки должны вести на Яндекс Карты, для остальных стран — на Google Maps;
- ссылки DIKIDI, YCLIENTS или другой онлайн-записи;
- отдельные ссылки записи для конкретных услуг, если они переданы.

### Услуги

- категории и их порядок;
- название каждой услуги;
- цена или диапазон цены;
- длительность;
- описание;
- варианты услуги с отдельными длительностями и ценами.

Явный список услуг из чата является окончательным источником правды. Агент сам превращает его в структуру `services`. Если пользователь дал только ссылку на официальный каталог/онлайн-запись, можно извлечь видимые услуги оттуда и пометить неясные позиции в едином запросе; нельзя добавлять услуги по догадке.

### Контент

- реальные отзывы только с оценкой 5★, автором, текстом, источником и ссылкой, если она дана;
- сотрудники: имя, специализация, описание, категории услуг, работы и связанные отзывы — только если эти данные переданы;
- логотип и изображения по контракту `RULES.md`.

## Минимум для production

Для выпуска нужны:

- название, страна/языки, короткие `city`/`address` для интерфейса и полный `fullAddress`;
- график или подтверждённый режим работы по записи;
- хотя бы один настоящий способ связи/записи;
- рабочие `contacts.mapUrl` и `contacts.mapEmbedUrl` правильного провайдера для страны;
- хотя бы одна настоящая услуга;
- `hero.webp` — главное фото салона;
- `profile.webp` — отдельное фото для «О салоне»;
- от 1 до 25 реальных `gallery-XX.webp`;
- все обязательные переводы для выбранной страны.

Логотип необязателен. Отзывы и команда также необязательны как клиентские данные: без отзывов остаётся нейтральное состояние, а без команды интерфейс показывает четыре системные некликабельные карточки «Мастер» без выдуманных персональных данных. `team-XX.webp` добавляется только вместе с конкретными данными о мастере. `heroDescription` и `about` уже заполнены утверждённым универсальным текстом и не запрашиваются у клиента.
